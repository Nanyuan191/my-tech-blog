## 四、关闭程序的影响评估

### 现在关闭 → **完全安全**

| 关闭什么 | 影响 |
|---|---|
| 前端终端（5173） | 只是停止开发服务器，**源码不动** |
| 后端终端（3000） | 只是停止 Node 进程，**源码不动** |
| Docker Desktop | 容器停止，但 MySQL 数据存在**命名卷** `blog-system_db_data` 里，**持久化**，不会丢 |
| VS Code / 直接关机 | **唯一注意点**：没按过 `Ctrl+S` 的编辑会丢。保存过的文件不受影响 |

**唯一的雷**：绝对不要执行 `docker compose down -v`。参数 `-v` 会删除数据卷 = **删库**。日常停服用 `docker compose down`（不带 `-v`）或直接关 Docker Desktop。

### 以后哪些阶段「中途关闭」有风险

| 阶段 | 风险 | 应对 |
|---|---|---|
| **S5 Docker 构建进行中** | 低 —— 镜像构建到一半，重跑即可 | 等 `docker compose up -d --build` 跑完再关 |
| **数据库迁移进行中**（`prisma migrate`） | ⚠️ **最高** —— 迁移若写到一半中断，可能留下"半应用"的表结构 | 迁移期间不要关任何东西，等它打印完成 |
| **S7 部署到服务器时** | 本地关机**不影响服务器**（容器自愈重启） | 但 SSH 会话会断，正在上传的文件要重传 |
| **git push 进行中** | 低 —— 重新 push 即可 | — |
| 日常写代码 | 无 | 保存即可 |

**通用习惯**：关闭前扫一眼"有没有正在写入的操作"（构建、迁移、下载）。

## 五、下次开机恢复步骤

```bash
# 1. 先开 Docker Desktop，等左下角变绿「Engine running」

# 2. VS Code 打开项目（双击 打开VSCode.bat）

# 3. 终端 1：起数据库
docker compose up -d db

# 4. 终端 2：起后端（此终端不能关）
cd apps/api && npm run dev

# 5. 终端 3：起前端（此终端不能关）
cd apps/web && npm run dev
```

**访问地址**
- 首页：`http://localhost:5173`
- 登录：`http://localhost:5173/login`（账号 `admin` / `admin123456`）
- 后台：`http://localhost:5173/admin`

**注意**：`/admin` 刷新会跳回登录页 —— 这是**有意设计**（token 只存内存防 XSS），不是 bug。
