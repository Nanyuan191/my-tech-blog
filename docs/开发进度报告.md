### S5 排障记录（答辩彩蛋素材）

三个真实问题，都是「本地能跑、容器里跑不了」的典型：

1. **构建上下文过大** —— 根目录有 `node_modules`（几百 MB），会整包传给 daemon。
   → 补 `.dockerignore`，上下文从数百 MB 降到 **263 KB**。

2. **`apps/api/node_modules: not found`** —— npm workspaces 会把依赖**提升**到根 `node_modules`，子包目录下根本没有。
   → 删掉 Dockerfile 里对子包 node_modules 的 COPY；Node 的模块解析本来就会逐级向上查找。

3. **Prisma Client 生成位置** —— `prisma generate` 写在 builder 阶段，产物落在 `node_modules/.prisma`。
   原先 runner 阶段从 **deps** 拷 node_modules → 运行时会报 `@prisma/client did not initialize yet`。
   → 改成从 **builder** 拷。（这类问题不报构建错，只在运行时炸，最隐蔽。）

4. **国内网络两处坑** —— npm 官方源超时 → 默认走 npmmirror；
   Prisma 引擎二进制从 `binaries.prisma.sh` 下载 → 保留可选镜像参数（见 `apps/api/Dockerfile` 顶部注释）。

## 五、关闭程序的影响评估

### 现在关闭 → **完全安全**

| 关闭什么 | 影响 |
|---|---|
| 前端终端（5173） | 只是停止开发服务器，**源码不动** |
| 后端终端（3000） | 只是停止 Node 进程，**源码不动** |
| Docker Desktop | 容器停止，但 MySQL 数据存在**命名卷** `blog-system_db_data` 里，**持久化**，不会丢 |
| VS Code / 直接关机 | **唯一注意点**：没按过 `Ctrl+S` 的编辑会丢。保存过的文件不受影响 |

**唯一的雷**：绝对不要执行 `docker compose down -v`。参数 `-v` 会删除数据卷 = **删库**。
日常停服用 `docker compose down`（不带 `-v`）或直接关 Docker Desktop。

### 以后哪些阶段「中途关闭」有风险

| 阶段 | 风险 | 应对 |
|---|---|---|
| **S5 Docker 构建进行中** | 低 —— 镜像构建到一半，重跑即可 | 等构建跑完再关 |
| **数据库迁移进行中**（`prisma migrate`） | ⚠️ **最高** —— 迁移若写到一半中断，可能留下"半应用"的表结构 | 迁移期间不要关任何东西 |
| **S7 部署到服务器时** | 本地关机**不影响服务器**（容器自愈重启） | 但 SSH 会话会断，正在上传的文件要重传 |
| **git push 进行中** | 低 —— 重新 push 即可 | — |
| 日常写代码 | 无 | 保存即可 |

## 六、装修阶段：什么时候做、边界在哪

### 顺序：**S6 → S7 上线 → S8 附加 → 装修 → S9 答辩素材**

**为什么装修排在这么后面？**

1. 前端镜像是**多阶段构建**（builder 里跑 `vite build`，产物 COPY 进 nginx）→
   **改任何前端源码（含 CSS）都必须重建镜像**，否则容器里跑的还是旧产物。
2. S9 的截图/录屏素材**会因装修而过期** → 先拍就得重拍，所以放最后。
3. 装修反而是**演示 CI/CD 的最佳素材**：push 一下自动构建上线，现场可视化。

### 装修的边界（红线）

| 可以做 | 不要碰 |
|---|---|
| `<style>` / CSS | `<script setup>` 里的逻辑 |
| 模板静态结构（加 class、包裹 div） | 接口调用、请求参数 |
| 新增独立组件（如 Navbar） | 路由表 |

**第一件该做的事**：`App.vue` 目前只有 `<router-view />`，**没有导航栏** ——
所以首页没有登录入口，只能手输 `/login`。补一个 Navbar 是装修的第一步。
