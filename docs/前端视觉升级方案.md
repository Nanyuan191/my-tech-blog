# 前端视觉升级方案（配图 + 版式）

> 状态：**方案待确认**，代码未动。
> 前置：S8（导航栏 / 深色模式 / 代码复制 / 改密码 / 安全清理 / 视觉提升）+ 点赞 已完成并上线。

## 一、现状盘点（实测）

| 项目 | 现状 | 结论 |
|---|---|---|
| `apps/web/public/` 目录 | **不存在** | 全站 0 张图片、无 favicon（浏览器请求 `/favicon.ico` 得 404） |
| 页面背景 | 白底 + 两层极淡径向渐变（`--page-bg-layer`） | 渐变太淡，肉眼几乎看不出 → **"单调"的直接原因** |
| 文章 `coverImage` 字段 | 数据库有字段，但 seed 里**没填值** | 想上封面图，得先把默认图补上 |
| 内容宽度 | `--content-width: 820px`（首页/详情页统一） | 单栏适合阅读，但配图后偏窄 |
| 总资源体积 | JS 58KB + CSS 370KB（含 Element Plus） | 增量预算约 **400KB**，超出会明显拖慢首屏 |

**网络前提（决定图片预算）**：轻量服务器**出网带宽 2Mbps ≈ 250KB/s**（访客下载走这个）。
→ 因此首屏新增图片总量**控制在 400KB 以内**，单张不超过 200KB。
（今天实测南大通道 1.7MB/s 那是**入网**方向，和访客下载不是一个通道，别混。）

## 二、三层改造清单

### 第 1 层 · 背景层（解决"单调"，成本极低）

| # | 做法 | 体积 | 效果 |
|---|---|---|---|
| 1 | 背景叠加**点阵/网格纹理**（SVG data-uri） | ~1KB | 立刻有"技术感"，不再是一片白 |
| 2 | 顶部光斑**加深饱和度**，并加第三个斜向色斑 | 0KB | 首屏有"打光"层次 |
| 3 | 正文区加一层**极淡的分栏底线**（可选） | 0KB | 长文更有秩序 |

> 深浅色各一套变量（沿用现有 `theme.css` 机制），切换主题不用改页面。

### 第 2 层 · 图片层（"加图"）

| # | 位置 | 方案 | 体积 | 备注 |
|---|---|---|---|---|
| 1 | 导航栏左侧 **logo** | 内联 SVG（`</>` 符号或几何标） | <1KB | 顺便修掉 favicon 404 |
| 2 | 首页 **hero 横幅** | 1 张抽象科技图，压在文字后面 | 120~180KB | 唯一需要 AI 生成的图 |
| 3 | 文章卡片 **缩略图** | CSS 渐变 + 分类字母（零图片） | 0KB | `coverImage` 为空时自动兜底；填了就显示真图 |
| 4 | 详情页 **顶部封面** | 复用同一套兜底图 | 0KB | 有 `coverImage` 时优先 |
| 5 | 空状态 / 404 | 内联 SVG 小插画 | <2KB | 细节加分 |

**关键取舍**：只有第 2 项需要真图片文件。其余全部用 CSS/SVG —— 因为访客带宽只有 2Mbps，图片越多首屏越慢，而 SVG 是矢量、任何分辨率都不糊，答辩时是很好的"性能意识"论据。

### 第 3 层 · 版式层（排版规格）

| 项目 | 现在 | 建议 | 理由 |
|---|---|---|---|
| 导航栏高度 | 60px | 60px（不变） | 已合适 |
| hero 区 | 纯文字，高约 140px | **图文横幅，高 220~280px** | 首屏有"封面感" |
| 列表页宽度 | 820px | **960px** | 容纳"左图右文"卡片 |
| 阅读页宽度 | 820px | **760px**（收窄） | 每行 70~80 字符最舒服 |
| 卡片布局 | 纯文字 | **左图右文**（图 200×130），<768px 堆叠 | 一屏看到更多信息层次 |
| 卡片间距 | 18px | 24px | 配图后需要更多呼吸 |
| 页脚 | 无 | **新增**：版权 + 技术栈 + 备案/建站说明 | 三段式（封面-内容-页脚）更完整 |
| 正文 | 16px / 行高 1.85 | 保持 | 已经不错 |

响应式断点统一为 **768px**（平板/手机）。

## 三、图片来源：三个选项对比

| 选项 | 成本 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. AI 生成 1 张 hero 图 + 其余 SVG** | 低 | 出图好看、可控、体积可控 | 需人工挑图 + 压缩 | ★ **推荐** |
| B. 全部 CSS/SVG（零图片） | 最低 | 0KB、永不失效、矢量化 | 视觉偏"性冷淡"，不算"加了图" | 备选 |
| C. 外链图床 / CDN | 低 | 不占服务器带宽 | 外链会失效、http 混合内容风险、国内加载慢 | ✗ 不推荐 |

> A 方案落地细节：生成 → 裁到 1600×520 → 压到 150KB 内（jpg 质量 78）→ 放进 `apps/web/src/assets/`，
> 由 Vite 打包（文件名带 hash，可长期缓存）。

## 四、实施分批（每批可独立验收）

| 批次 | 内容 | 是否要重建镜像 | 风险 |
|---|---|---|---|
| **V1** | 背景层（纹理 + 光斑）+ logo + favicon + 页脚 | 只重建 web（76MB） | 低 |
| **V2** | hero 横幅图 + 卡片左图右文 + 宽度/间距规格 | 只重建 web | 中（图片体积） |
| **V3**（可选） | 空状态插画、详情页封面、目录 TOC | 只重建 web | 低 |

> 全程**不碰后端**：不动 `apps/api`、不动数据库、不动接口 → 不需要拉 788MB 的 api 镜像。

## 五、风险与红线

1. **体积红线**：单张图 ≤200KB，首屏新增总量 ≤400KB。超了就压缩或降分辨率。
2. **深色模式必须同步**：背景纹理和图片遮罩都要在 `html.dark` 下有对应值，否则深色下会"糊成一片"。
3. **不碰逻辑**：只改 `<style>` / 模板静态结构 / 新增组件；`<script setup>` 里的逻辑、接口、路由一律不动。
4. **图片不能有版权问题**：优先 AI 生成或自绘 SVG，不用网上随便下的图。
5. **验收必须强刷**：`Ctrl+F5`，否则看到的是浏览器缓存的旧产物。
