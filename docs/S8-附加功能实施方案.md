## 一、S8 的核心工程约束（决定了做什么、怎么做）

| 约束 | 事实 | 结论 |
|---|---|---|
| 改后端 = 重建 **api 镜像（788MB）** | 今天服务器拉这个镜像花了一小时 | **S8 一律不动后端** |

| 考核窗口仅 15 天 | 已用 2 天 | 功能宁少勿贪，每项都要能讲清楚 |

**结论：S8 = 纯前端附加功能 + 界面装修，一次改完、一次推送、一次重建。**

## 三、逐项实现要点

### 1. 导航栏 Navbar（`App.vue`）

```
┌──────────────────────────────────────────────┐
│  我的技术博客       首页   后台   [🌙]  [登录] │
└──────────────────────────────────────────────┘
```
- 左侧站名；右侧：首页 / 后台（登录后才显示）/ 深色切换按钮 / 登录·退出按钮
- 退出调用 `auth.logout()`（store 已有），调完 `router.push('/')`
- 登录态读 `auth.isLoggedIn()` —— ⚠️ **必须带括号**（它是函数不是属性；漏括号不报错但守卫会失效）

### 2. 深色模式（element-plus ^2.9.1 原生支持）

- **原理**：在 `<html>` 标签上加/删 `dark` 这个 class，Element Plus 的深色变量自动生效
- 新增 `stores/theme.ts`（pinia）：`mode = 'light'|'dark'`、`toggle()`、启动时读 `localStorage['blog-theme']`
- `main.ts` 增加两行：
  ```ts
  import 'element-plus/theme-chalk/dark/css-vars.css';
  import './styles/theme.css';
  ```
- 新增 `styles/theme.css`：定义自己的语义变量（`--bg / --text / --text-muted / --border / --card`），浅深两套；**各视图里写死的颜色（`#999`、`#eee`、`#282c34`）改成语义变量**
- ⚠️ 边界：只动 `<style>` 和模板静态结构，不动 `<script setup>` 的业务逻辑

### 3. 代码块一键复制（`PostView.vue`）

- 实现：`watch(renderedContent)` → `nextTick()` → 遍历 `.content pre`，每个包一层容器并插入"复制"按钮 → 点击复制 `pre.innerText` → 按钮文案变"已复制"1.5 秒
- **⚠️ 提前排雷（重要）**：`navigator.clipboard` **只在安全上下文可用**（HTTPS 或 localhost）。我们的线上是 `http://129.28.26.104:8080`，**不是安全上下文**，Chrome 里 `navigator.clipboard` 可能直接是 `undefined`。
  → 必须写降级：优先用 `navigator.clipboard`，不可用时退回 `document.execCommand('copy')` + 临时 `<textarea>`。
  → 答辩话术："复制功能我做了安全上下文降级，因为我们的站点跑在非 HTTPS 的 8080 端口上" —— 这是能显出功力的细节。

### 4. 修改密码页（用现成后端接口，零后端改动）

- 后端接口已存在：`PUT /api/auth/password`，body `{ oldPassword, newPassword }`，需 `Authorization: Bearer <token>`
- 校验规则（已核）：`oldPassword` 非空；`newPassword` **6~128 位**（8 位带符号完全合规）
- 新增 `api/auth.ts`：
  ```ts
  export function changePassword(oldPassword: string, newPassword: string, token: string) {
    return request.put('/auth/password', { oldPassword, newPassword },
      { headers: { Authorization: `Bearer ${token}` } });
  }
  ```
  ⚠️ `request.ts` 拦截器**不自动带 token**（故意不 import store，防循环依赖）→ 必须手动传
- 新增 `views/PasswordView.vue`：两个密码框 + 确认框 → 前端校验（≥6 位、两次一致、新旧不同）→ 提交 → 成功提示"请重新登录" → `auth.logout()` → 跳 `/login`
- `router/index.ts` 加一条：`{ path: '/password', component: PasswordView, meta: { requiresAuth: true } }`
- `views/AdminView.vue` 头部按钮区加一个「改密码」按钮
- ⚠️ 改完密码后 access token 仍在内存里有效直到过期 —— 所以**主动 logout 强制重新登录**，逻辑才闭环

### 5. 安全清理（✅ 2026-10-02 已完成）

| 位置 | 原状 | 改成（均已落实） |
|---|---|---|
| `LoginView.vue` | `const password = ref('admin123456')` | `ref('')` ✅ |
| `LoginView.vue` 提示文案 | "默认账号：admin / admin123456" | "仅站长可登录（后台管理用）" ✅ |
| 8 份文档共 11 处 | 写着真实默认密码 | 一律占位符 `admin / 你的管理员密码` ✅ |
| `seed.ts` 兜底值 | `SEED_ADMIN_PASSWORD ?? '...'` | **有意保留**（本地开发用），线上真实密码已改 ✅ |

**注意**：git 历史里仍有旧密码 —— 但**改掉线上密码后它就作废了**，历史留着不影响安全。

## 六、风险清单（开工前已知）
