
**⚠️ 本机最大的环境坑：HTTP 代理端口每次会话都可能变。**

```powershell
# 先看当前端口
$env:HTTPS_PROXY        # 形如 http://127.0.0.1:54809
```

- 工具侧的 PowerShell **必须走代理**才能出网（直连 npm / npmmirror 都超时）。
- 但 **Docker 容器有直连网络**，构建镜像时**不要**给容器传代理。
- npm 配置里若写死了旧端口，要同步更新：
  ```powershell
  npm config set proxy  http://127.0.0.1:<新端口>
  npm config set https-proxy http://127.0.0.1:<新端口>
  ```

**其他环境事实**

- 工具会话**不是管理员**；系统级安装必须船长用管理员 PowerShell 执行。
- `bash` 工具在本机不可用（PortableGit 缺 coreutils）→ **一律用 PowerShell 工具**。
- PowerShell 工具 stdout 经常丢失 → 可靠做法是 `Out-File` 写文件后用 Read 工具读。
- 执行策略禁 `npm.ps1` → 用绝对路径 `npm.cmd` / `npx.cmd`。

## 5. 关键事实速查（不要重新试错）

### 接口契约（已实测）

- 列表：`{ success, data: Article[], pagination }` —— **`data` 直接是数组**，`pagination` 同级。
- 列表 **不返回 `content`** → 编辑时必须单独拉详情 `GET /posts/:slug`，**且要带 token**（否则草稿 404）。
- 详情走 `optionalAuth`：匿名看已发布 200 / 匿名看草稿 404 / 带 token 看草稿 200。
- 写操作在前台路径：`POST /posts`、`PUT /posts/:id`、`DELETE /posts/:id`（均需 token）。
- 后台列表：`GET /posts/admin`（需 token）。
- **路由注册顺序**：固定路径（`/stats`）与写操作必须排在 `/:slug` **之前**。
- 登录入参是 `{ username, password }`（不是 email）；返回 `data.accessToken` + httpOnly Cookie。

### 常用命令

```bash
# 开发模式
docker compose up -d db
cd apps/api && npm run dev     # 3000
cd apps/web && npm run dev     # 5173

# 容器模式（一键整站）
docker compose up -d --build   # → http://localhost:8080

# 查数据库（Prisma 模型 Article → 表 articles，小写复数）
docker exec blog-db mysql -uroot -proot_pass_2026 -e "select id,title,status from blog.articles;"
```

### 踩过的坑（别重复踩）

1. **`.dockerignore` 必须有** —— 否则整包 node_modules 进构建上下文（这次从数百 MB 降到 263 KB）。
2. **npm workspaces 的子包没有 `node_modules`** —— 依赖全提升到根，Dockerfile 里不要 COPY 子包 node_modules。
3. **Prisma Client 生成在 `node_modules/.prisma`** —— 运行时镜像的 node_modules 必须从 builder 阶段拷（不是 deps 阶段），否则报 `@prisma/client did not initialize yet`。
4. **`prisma.config.ts` 存在时 CLI 不自动读 `.env`** → 该文件首行必须 `import 'dotenv/config'`。
5. **Vue 路由参数变化不重建组件** → `PostView` 要用 `watch(() => route.params.slug, ..., { immediate: true })`。
6. **`auth.isLoggedIn` 是函数** → 路由守卫必须写 `auth.isLoggedIn()`，漏括号会静默失效（不登录也能进后台）。
7. **`docker compose down -v` 会删数据卷 = 删库**，永远别用。

### 红线

- **不碰** `apps/web/src/` 下的业务文件 —— 那是船长自己敲的成果。
- 改前端任何源码（含 CSS）后，**必须重建前端镜像**才在 8080 生效。
- 提交信息含中文时用 `git commit -F <utf8文件>`，避免 PowerShell 传参编码问题。

## 6. 装修阶段：什么时候做、边界在哪

**顺序：S6 → S7 上线 → S8 附加 → 装修 → S9 答辩素材。**

原因：
1. 前端镜像是多阶段构建，改 CSS 也要重建镜像，否则容器里还是旧产物。
2. S9 的截图/录屏会因装修而过期 → 放最后拍。
3. 装修正好可以当 CI/CD 的演示素材（push 一下自动上线）。

**边界：可以做 `<style>` / 模板静态结构 / 新增独立组件；不要碰 `<script setup>` 逻辑、接口调用、路由。**

**第一件事**：`App.vue` 只有 `<router-view />`，没有导航栏 → 首页没有登录入口，只能手输 `/login`。
