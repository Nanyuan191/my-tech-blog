## 二、怎么判断「我现在在哪个界面」

三秒判定法：

- 看**地址栏**：
  - 有 `github.com` → ②
  - 有 `console.cloud.tencent.com` → ③
  - 有 `129.28.26.104:8080` → ⑤
  - 是 `localhost:5173` → ⑤ 的本地版（开发用）
- 看**窗口长相**：
  - 黑底白字、每行开头是 `ubuntu@VM-...:~$` → ④ 服务器终端
  - 白底、左边有文件树 → ① 本地 VS Code
  - 白底、有「登录 / 更多 / 重置密码」按钮列 → ③ 腾讯云控制台

> 一句话记法：**③ 是"管服务器的网页"，④ 是"服务器本身"**。网页上按钮点不动时，命令要去 ④ 里敲。

## 四、当前所在的这一步（④ OrcaTerm 终端）

**背景**：GHCR（GitHub 镜像仓库）在服务器上拉取极慢（实测 25KB/s），api 镜像 788MB，CI 自动部署会超时。所以改成**在服务器上手动拉**，拉完再手动起容器。

**在 ④ OrcaTerm 终端里逐行执行**（一行一条，敲完回车等结果，不要一次全贴）：

```bash
# 1. 先拉小的（web 76MB）测个速，能下来说明通道通
docker pull ghcr.nju.edu.cn/nanyuan191/my-tech-blog/web:latest

# 2. 再拉大的（api 788MB），慢是正常的，断了就重复执行同一条，会续传
docker pull ghcr.nju.edu.cn/nanyuan191/my-tech-blog/api:latest

# 3. 拉完把名字改回官方名，否则 compose 文件找不到
docker tag ghcr.nju.edu.cn/nanyuan191/my-tech-blog/web:latest ghcr.io/nanyuan191/my-tech-blog/web:latest
docker tag ghcr.nju.edu.cn/nanyuan191/my-tech-blog/api:latest ghcr.io/nanyuan191/my-tech-blog/api:latest

# 4. 确认两个镜像都在本地了（应看到 web 和 api 两行）
docker images | grep my-tech-blog

# 5. 进项目目录，把镜像仓库地址告诉 compose，然后起三个容器
cd ~/blog
export IMAGE_PREFIX="ghcr.io/nanyuan191/my-tech-blog"
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d

# 6. 看三个容器是否都 Up（healthy）
docker ps
```

**然后切到 ⑤ 本地浏览器**，打开 `http://129.28.26.104:8080` 验收。

## 五、常见「界面走错」的坑

1. **在 ③ 控制台里找地方敲 `docker pull`** —— 控制台没有命令输入框，命令永远在 ④。
2. **在 ④ 里想编辑本地文件** —— ④ 是服务器，本地文件在 ①。
3. **在 ② GitHub 网页上直接改代码** —— 会造成本地和远程版本分叉，下次推送冲突。
4. **验收时只看本地 `localhost:8080`** —— 那证明不了公网可访问，必须用 ⑤ 的 `http://公网IP:8080`，最好再用手机 4G 试一次。
5. **③ 改了防火墙却忘了 ④ 里容器没起** —— 防火墙是"门开了"，容器是"屋里有没有人"，两件事都要做。
