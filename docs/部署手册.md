# 部署手册

> 从零到上线的完整步骤。每一步都有验证方法 —— **没验证过的步骤等于没做**。

---

## 阶段一：本地跑通（无需服务器）

### 1.1 前置检查

```bash
node -v      # 期望 v20 或更高
npm -v
docker -v
docker compose version
```

**验证方法**：四条命令都能输出版本号。任一报"不是内部或外部命令"，说明该工具未安装或 PATH 未刷新（**新开一个终端窗口**再试）。

### 1.2 启动数据库容器

```bash
cd blog-system
docker compose up -d db
```

**验证方法**：

```bash
docker compose ps
```

期望看到 `blog-db` 状态是 `Up (healthy)`。

⚠️ **注意 `Up` 和 `Up (healthy)` 的区别**：刚启动的十几秒内是 `Up (health: starting)`，此时数据库还在初始化，连不上。必须等到 `healthy` 才是真的可用。

**如果一直是 `health: starting` 超过 1 分钟**：

```bash
docker compose logs db
```

常见原因：
- 端口 3306 被本机已安装的 MySQL 占用 → 改映射为 `3307:3306`，同时改 `DATABASE_URL` 的端口
- 磁盘空间不足 → `docker system df` 查看

### 1.3 安装依赖

```bash
npm install
```

**验证方法**：`node_modules` 目录存在，且根目录 `node_modules/.prisma` 下有内容。

### 1.4 配置环境变量

```bash
cp apps/api/.env.example apps/api/.env
```

`.env` 内容说明：

| 变量 | 作用 | 生产环境注意事项 |
|---|---|---|
| `DATABASE_URL` | 数据库连接串 | 密码必须换强密码 |
| `JWT_SECRET` | 令牌签名密钥 | **必须换！** 用下面命令生成 |
| `JWT_ACCESS_EXPIRES` | access token 有效期 | 保持 2h |
| `JWT_REFRESH_EXPIRES` | refresh token 有效期 | 保持 7d |

生成随机密钥：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### 1.5 建表并写入种子数据

```bash
npm run prisma:migrate --workspace=apps/api
npm run seed --workspace=apps/api
```

**验证方法**：seed 会打印

```
✓ 管理员账号：admin（密码：admin123456）
✓ 分类 3 个
✓ 标签 8 个
✓ 示例文章 3 篇
```

### 1.6 启动服务

```bash
npm run dev
```

**验证方法（三个都要过）**：

1. 浏览器打开 `http://localhost:3000/api/health`
   期望：`{"ok":true,...,"database":{"ok":true,...}}`
   ⚠️ 如果 `database.ok` 是 `false`，说明数据库没连上，回去查 1.2 和 1.4

2. 浏览器打开 `http://localhost:3000/api/posts`
   期望：返回 3 篇示例文章的 JSON 数组

3. 浏览器打开 `http://localhost:5173`
   期望：看到博客首页

### 1.7 验证后台鉴权

```bash
# 登录，拿到 token
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123456"}'
```

期望返回：

```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOi...",
    "user": { "id": 1, "username": "admin", "role": "ADMIN" }
  }
}
```

**验证鉴权是否真的生效**（这一步很关键）：

```bash
# 不带 token 访问后台接口 —— 应该被拒绝
curl http://localhost:3000/api/posts/admin

# 期望：{"success":false,"message":"缺少访问令牌"}
```

**如果这个请求成功了，说明鉴权没生效，是严重问题** —— 任何人都能访问后台。

## 阶段二：Docker 全栈验证

### 2.1 一键启动

```bash
docker compose down -v     # 清掉之前的数据，从干净状态开始
docker compose up -d --build
```

首次构建约 3-5 分钟（要装依赖、编译 TS、构建前端）。

**验证方法**：

```bash
docker compose ps
```

期望三个容器全部 `Up`，且 `blog-db` 和 `blog-api` 是 `(healthy)`。

### 2.2 验证全链路

| # | 操作 | 期望结果 |
|---|---|---|
| 1 | `curl http://localhost:8080/api/health` | `{"ok":true,...}` |
| 2 | `curl http://localhost:8080/api/posts` | 文章列表 JSON |
| 3 | 浏览器打开 `http://localhost:8080` | 看到博客首页 |
| 4 | 刷新 `http://localhost:8080/posts/xxx` | **不报 404**（SPA 回退生效） |

**第 4 条是重点**：如果刷新 404，说明 `nginx.conf` 里的 `try_files` 没生效，回去检查文件是否正确 COPY 进镜像。

### 2.3 验证数据持久化

```bash
docker compose restart db
sleep 20
curl http://localhost:8080/api/posts
```

期望：**文章还在**。如果数据没了，说明 `db_data` 卷没配好。

### 2.4 验证优雅退出

```bash
docker compose stop api
docker compose logs api | tail -20
```

期望日志里能看到：

```
收到 SIGTERM，开始优雅退出...
HTTP 服务已关闭
数据库连接已断开
```

## 阶段三：推送代码到 GitHub

### 3.1 配置 Git 身份

⚠️ **这一步必须先做**，否则提交记录里是"未知用户"。

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```

**验证方法**：

```bash
git config --global --list | findstr user
```

期望显示你填的真实信息。如果显示的是 `你的名字` / `你的邮箱`，说明还是占位符，需要重新执行。

### 3.2 生成 SSH 密钥

```bash
ssh-keygen -t ed25519 -C "你的邮箱@example.com"
```

一路回车（密钥路径用默认，密码可留空）。

**验证方法**：

```bash
type %USERPROFILE%\.ssh\id_ed25519.pub
```

复制输出的内容（以 `ssh-ed25519` 开头的整行）。

### 3.3 添加到 GitHub

1. GitHub → 右上角头像 → **Settings**
2. 左侧 **SSH and GPG keys** → **New SSH key**
3. Title 随便填（如 `我的笔记本`），Key 粘贴刚才复制的内容
4. **Add SSH key**

**验证方法**：

```bash
ssh -T git@github.com
```

期望：`Hi 你的用户名! You've successfully authenticated...`

⚠️ 第一次会问 `Are you sure you want to continue connecting?` 输入 `yes` 回车。

### 3.4 创建仓库并推送

在 GitHub 上新建仓库（**不要**勾选 Add README / .gitignore，因为本地已经有了）。

```bash
cd blog-system
git init
git add .
git commit -m "feat: 初始化博客系统（后端 API + Docker 化 + CI/CD）"
git branch -M main
git remote add origin git@github.com:你的用户名/仓库名.git
git push -u origin main
```

**验证方法**：刷新 GitHub 页面，代码都在。且 **Actions 标签页**应该有一条流水线在跑。

## 阶段四：配置 CI/CD 密钥

在 GitHub 仓库 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**，逐个添加：

| Secret 名称 | 值 | 说明 |
|---|---|---|
| `SERVER_HOST` | 服务器公网 IP | 如 `123.45.67.89` |
| `SERVER_USER` | `root` 或 `ubuntu` | 腾讯云轻量默认是 `ubuntu` |
| `SERVER_SSH_KEY` | 服务器私钥内容 | 见下方说明 |
| `MYSQL_ROOT_PASSWORD` | 强密码 | 数据库 root 密码 |
| `MYSQL_PASSWORD` | 强密码 | 应用账号密码 |
| `JWT_SECRET` | 随机长串 | 用 1.4 的命令生成 |

### `SERVER_SSH_KEY` 怎么填

**这是最容易搞错的一项。** 需要把**本地私钥**（不是 `.pub`）的完整内容贴进去：

```bash
type %USERPROFILE%\.ssh\id_ed25519
```

输出应该是这样（**包含首尾两行，一行都不能少**）：

```
-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAAEbm9uZQAAAAAAAAABAAAAMwAAAAtzc2gtZW
...（中间多行）...
-----END OPENSSH PRIVATE KEY-----
```

同时需要把公钥加到服务器的 `~/.ssh/authorized_keys` 里。

## 阶段五：服务器初始化

### 5.1 购买与登录

购买腾讯云**轻量应用服务器**：

- 地域：选国内（如上海、广州）—— 走 IP 直连方案，无需备案
- 镜像：**Ubuntu 22.04 LTS**
- 规格：2核2G 起

购买后在控制台**重置密码**，然后用 SSH 登录：

```bash
ssh ubuntu@你的公网IP
```

### 5.2 放行端口（关键！）

腾讯云轻量应用服务器的**防火墙默认只开 22、80、443**。我们用的是 8080，必须手动放行。

控制台 → 服务器详情 → **防火墙** → **添加规则**：

| 应用类型 | 协议 | 端口 | 来源 |
|---|---|---|---|
| 自定义 | TCP | 8080 | 0.0.0.0/0 |

⚠️ **这一步不做，浏览器访问会一直超时**，而服务器上 `docker compose ps` 显示一切正常 —— 这是最容易被卡住的地方。

**验证方法**（在本地执行）：

```bash
curl -v http://你的公网IP:8080
```

如果返回 `Connection refused`，是服务没起；如果**超时无响应**，八成是防火墙没放行。

### 5.3 安装 Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

**验证方法**：**退出 SSH 重新登录**（让用户组变更生效），然后：

```bash
docker run --rm hello-world
```

期望看到 `Hello from Docker!`。

⚠️ 如果拉镜像超时，说明国内访问 Docker Hub 不稳。配置镜像加速：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.1panel.live"
  ]
}
EOF
sudo systemctl restart docker
```

### 5.4 创建部署目录

```bash
mkdir -p ~/blog && cd ~/blog
```

目录内容由 CI/CD 自动上传，不需要手动创建文件。

## 阶段六：首次部署

### 6.1 触发部署

在本地推一次代码（或到 GitHub 上手动点 **Run workflow**）：

```bash
git commit --allow-empty -m "chore: 触发首次部署"
git push
```

### 6.2 观察流水线

GitHub → **Actions** → 点最新那条 → 依次看到三个 job：

```
✓ Lint & Type Check
✓ Build & Push Images
✓ Deploy to Server
```

**如果 Deploy 失败**，常见原因：

| 报错 | 原因 | 解决 |
|---|---|---|
| `Permission denied (publickey)` | `SERVER_SSH_KEY` 填错，或服务器没加公钥 | 检查私钥完整性和 `authorized_keys` |
| `docker: command not found` | 服务器装完 Docker 没重新登录 | 退出 SSH 重连 |
| `unauthorized` 拉镜像失败 | GHCR 登录失败 | 检查仓库的 Packages 权限设置 |

### 6.3 服务器侧验证

```bash
ssh ubuntu@你的公网IP
cd ~/blog
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
```

期望三个容器 `Up`。

**查看日志排查问题**：

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs -f api
```

### 6.4 首次建表

容器首次启动时会自动执行 `prisma migrate deploy` 建表。但如果需要灌种子数据：

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api npx tsx prisma/seed.ts
```

## 阶段七：上线验证（必须项1）

### 7.1 验证清单

| # | 操作 | 期望 |
|---|---|---|
| 1 | `curl http://公网IP:8080/api/health` | `{"ok":true,...,"database":{"ok":true}}` |
| 2 | 浏览器打开 `http://公网IP:8080` | 博客首页正常显示 |
| 3 | 手机 4G 网络（不用 WiFi）打开同一地址 | 能打开 —— 证明是真正的公网可达 |
| 4 | 点进一篇文章，刷新页面 | 不 404 |
| 5 | 登录后台 → 发一篇新文章 | 发布成功，返回首页能看到 |
| 6 | 不带 token 请求 `/api/posts/admin` | 返回 401 |

**第 3 条最重要**：用手机流量而不是 WiFi，能排除"其实只在内网可达"的假象。这一条过了，必须项1 才算真的拿到。

### 7.2 记录交付信息

拿到链接后立刻记录下来，这是必须项1 的交付物：

```
主链接：http://<公网IP>:8080
健康检查：http://<公网IP>:8080/api/health
仓库地址：https://github.com/<用户名>/<仓库名>
Actions：https://github.com/<用户名>/<仓库名>/actions
```

## 阶段八：ICP 备案与域名（长期方案）

### 8.1 为什么需要备案

中国大陆节点的 **80 和 443 端口**必须完成 ICP 备案才能对外提供服务。备案未通过前绑定域名，访问会被运营商拦截。

我们的策略是先用 8080 端口交付（不受此限制），备案同步走流程。

### 8.2 备案流程

1. 在腾讯云控制台购买域名（或从其他注册商转入）
2. 控制台 → **备案** → 提交备案申请
3. 需要准备：身份证、服务器实例（需购买满 3 个月）、网站名称与简介
4. 腾讯云初审（1-2 天）→ 提交管局（3-20 工作日）
5. 备案通过后会收到短信通知

### 8.3 备案后的切换

备案通过后，改动量很小：

**① Nginx 监听 80 端口**

```yaml
# docker-compose.prod.yml
services:
  web:
    ports:
      - "80:80"      # 从 8080 改成 80
      - "443:443"
```

**② 加 HTTPS**

用 Caddy 替换 Nginx 可以自动申请和续期 Let's Encrypt 证书，配置只需三行：

```
blog.example.com {
    reverse_proxy web:80
}
```

或者继续用 Nginx + certbot。

**③ 更新交付链接**

`http://<IP>:8080` → `https://blog.example.com`

## 附录 A：常用命令速查

```bash
# ---- 本地开发 ----
npm run dev                              # 前后端一起跑
npm run dev:api                          # 只跑后端
npm run dev:web                          # 只跑前端

# ---- 数据库 ----
npm run prisma:migrate --workspace=apps/api    # 改 schema 后建迁移
npm run prisma:studio --workspace=apps/api     # 可视化查看数据
npm run seed --workspace=apps/api              # 灌种子数据

# ---- Docker ----
docker compose up -d                     # 启动
docker compose up -d --build             # 重新构建并启动
docker compose down                      # 停止（保留数据）
docker compose down -v                   # 停止并删除数据卷
docker compose logs -f api               # 跟踪后端日志
docker compose exec api sh               # 进容器

# ---- 服务器 ----
ssh ubuntu@公网IP
cd ~/blog
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs -f
docker system df                         # 查看磁盘占用
docker image prune -f                    # 清理旧镜像
```

## 附录 B：故障速查表

| 现象 | 可能原因 | 排查命令 |
|---|---|---|
| 访问超时 | 云服务商防火墙未放行 8080 | 控制台检查防火墙规则 |
| 访问被拒绝 | 服务没启动 | `docker compose ps` |
| `database.ok: false` | 数据库没连上 | `docker compose logs db` |
| 刷新页面 404 | Nginx 的 try_files 没配 | `docker compose exec web cat /etc/nginx/conf.d/blog.conf` |
| 拉镜像超时 | Docker Hub 被墙 | 配 registry-mirrors |
| 磁盘写满 | 旧镜像堆积 | `docker image prune -af` |
| 后端重启循环 | 数据库没就绪就启动 | 检查 healthcheck 和 depends_on |
| 登录后立刻掉线 | 前端没带上 Authorization 头 | 看浏览器 Network 面板 |
