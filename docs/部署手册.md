## 阶段一：本地跑通 ✅（2026-09-30 已完成，可跳过）

<details>
<summary>展开查看（仅出问题时回来复查）</summary>

### 1.1 前置检查

```bash
node -v      # 期望 v20 或更高
npm -v
docker -v
docker compose version
```

**判定标准**：四条命令都能输出版本号。任一报"不是内部或外部命令"，说明该工具未安装或 PATH 未刷新（**新开一个终端窗口**再试）。

### 1.2 启动数据库容器

```bash
cd blog-system
docker compose up -d db
docker compose ps
```

**判定标准**：`blog-db` 状态是 `Up (healthy)`。
⚠️ 刚启动十几秒是 `Up (health: starting)`，此时数据库还在初始化，连不上。**必须等到 `healthy`**。

### 1.3 安装依赖

```bash
npm install
```

**判定标准**：根目录 `node_modules/.prisma` 下有内容。

### 1.4 配置环境变量

```bash
copy apps\api\.env.example apps\api\.env
```

| 变量 | 作用 | 生产注意 |
|---|---|---|
| `DATABASE_URL` | 数据库连接串 | 密码必须换强密码 |
| `JWT_SECRET` | 令牌签名密钥 | **必须换！** |
| `JWT_ACCESS_EXPIRES` | access token 有效期 | 保持 2h |
| `JWT_REFRESH_EXPIRES` | refresh token 有效期 | 保持 7d |

生成随机密钥：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### 1.5 建表并写入种子数据

```bash
npm run prisma:migrate --workspace=apps/api
npm run seed --workspace=apps/api
```

**判定标准**：seed 打印 `✓ 管理员账号：admin`、`✓ 分类 3 个`、`✓ 标签 8 个`、`✓ 示例文章 3 篇`。（seed 的默认密码见终端输出；**上线后必须立即改掉**，见 5.3 安全提醒）

### 1.6 启动服务

```bash
npm run dev
```

**判定标准（三个都要过）**：

1. `http://localhost:3000/api/health` → `{"ok":true,...,"database":{"ok":true}}`
2. `http://localhost:3000/api/posts` → 3 篇示例文章 JSON
3. `http://localhost:5173` → 博客首页

### 1.7 验证后台鉴权

```bash
curl -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"<你的管理员密码>\"}"
```

**判定标准**：返回 `{"success":true,"data":{"accessToken":"eyJhbGciOi..."}}`。

**关键一步 —— 验证鉴权真的生效**：

```bash
curl http://localhost:3000/api/posts/admin
```

**判定标准**：`{"success":false,"message":"缺少访问令牌"}`。
如果这个请求成功返回了数据 → **鉴权没生效，是严重问题**，任何人都能进后台。

</details>

## 阶段三：推送代码到 GitHub ✅（2026-10-02 已完成）

<details>
<summary>展开查看（记录实际做法，供答辩说明）</summary>

**实际采用的方案是 HTTPS + Windows 凭据管理器，不是 SSH 密钥。** 原因：

- 这个项目只有你一个人开发，不需要 SSH 的多密钥管理
- HTTPS 走 Git Credential Manager，浏览器授权一次后凭据存进 Windows 凭据管理器，**之后推送不再弹授权**
- 服务器那边的 SSH 密钥是另一回事（部署用），见阶段六

**已完成的事实**：

| 项目 | 状态 |
|---|---|
| Git 身份 | 陈嘉乐（**仓库级**配置，非全局）；邮箱隐私问题见术语表「邮箱隐私」小节 |
| 远程仓库 | `https://github.com/Nanyuan191/my-tech-blog.git` |
| 推送方式 | 双击桌面 `推送到GitHub.bat`（工具沙箱连不到 GitHub，必须在本机会话执行） |
| 凭据 | 已存 Windows 凭据管理器（条目名 `git:https://github.com`） |

**日常推送命令**（或直接双击那个 .bat）：

```bash
git add .
git commit -m "说明这次改了什么"
git push
```

**判定标准**：GitHub 仓库页刷新后能看到新提交；`git status -sb` 显示 `## main...origin/main`（没有 `[ahead 1]` 之类）。

</details>

## 阶段四：购买腾讯云服务器（S7 第一步，从这里开始动手）

### 4.1 选什么配置

> **⭐ 使用时长只有 15 天（考核窗口）→ 按「月付」买，不要买年付。**详见 4.1.2。

#### 4.1.1 产品与规格

| 项目 | 选择 | 为什么 |
|---|---|---|
| 产品 | **轻量应用服务器（Lighthouse）** | 见 4.1.3 的对比结论 |
| 规格 | **2核2G**（3M 或 4M 带宽均可） | 三容器实测合计约 440MB，2G 绰绰有余 |
| 地域 | **上海 / 广州 / 南京** 等大陆节点 | 走 IP 直连，**无需备案**（用 8080 端口） |
| 镜像 | **系统镜像 → Ubuntu 22.04 LTS** | ⚠️ 不要选"WordPress 建站"等应用镜像，Docker 我们自己装 |

#### 4.1.2 时长怎么选（2026-10-02 购买页实测报价）

> 实测说明：网传"22 元/月活动价"在常规购买入口**看不到**（属新用户限时活动，入口和库存经常变）。**不要为找低价浪费时间**，购买页"新品专享型"标签下的日常价完全可接受。

| 方案 | 价格 | 判定 |
|---|---|---|
| 轻量 2核2G3M **月付**（入门型，购买页实测） | **35 元/月**（40GB SSD，含免费独立公网 IP） | ✅ **首选**：1 个月 35 元覆盖 15 天窗口 |
| 轻量 2核2G 月付（若能领到新用户活动价） | 约 22 元/月 | 🎁 有就用，没有别找 |
| 轻量 2核4G5M 月付 | 65 元/月 | 带宽更宽裕，非必需 |
| 轻量 2核2G3M **年付 4 折** | 192 元/年 | ❌ 只为 15 天使用，白付 11 个月（页面有 4 折诱惑，别点） |
| CVM **按量计费**（约 0.2 元/小时） | 15 天 ≈ 80–90 元 | ❌ 比月付更贵，还要自己管带宽和磁盘，忘关机就烧钱 |
| 新用户免费试用 1 个月 | 0 元 | 🎁 若能领到，优先用（注意读活动规则里的机型与流量限制） |

**⚠️ 时长默认陷阱**：购买页「时长」默认选的是 **1 年**，右下角总价会显示 192 元（4 折年付）——**必须手动改成 1 个月**，总价应变为 35 元左右再付款。

**⚠️ 系统镜像陷阱**：切到「基于操作系统镜像」后，**默认选中的是 OpenCloudOS 9**（腾讯自家 CentOS 系分支，用 yum/dnf）——**必须手动点「Ubuntu」瓦片**并选 **22.04 LTS**（手册基准版本；版本下拉默认排在最上面的 26.04 别选）。我们全部部署命令按 Ubuntu 的 `apt` 写，用 OpenCloudOS 每条命令都要现场翻译。

**⚠️ 表单重置陷阱**：**切换镜像/系统后，「时长」会被重置回 1 年（4 折，192 元）**。付款前用 3 秒口诀核对：**版本 22.04、时长 1 个月、总价 35 元**——三个都对再点「立即购买」。

**买多久的决策**：

```
答辩日 + 3 天缓冲 ≤ 到期日    ← 满足这条就够
```

保险做法：**买 1 个月**（覆盖 15 天窗口 + 缓冲）。若答辩时间可能推迟，直接买 2 个月（44 元）也远比年付便宜。

⚠️ **到期风险（重要）**：月付/试用到期后实例会**停机**，停机一段时间后数据会被回收。所以：
1. 在手机日历上设一个**到期前 3 天**的提醒
2. 到期前续费 1 个月（续费通常按日常价，约 40–50 元，仍在预算内）
3. 真到期的补救：数据在服务器上，重装一次只需重跑部署流程（用 Git 和小成本），损失可控 —— 但**答辩当天绝不能挂**，所以要设提醒

#### 4.1.3 为什么选轻量（Lighthouse）而不是 CVM

**轻量应用服务器面向的正是"小型网站 / Web 开发"场景**，和我们的项目定位完全吻合：

| 对比项 | 轻量 Lighthouse | 云服务器 CVM |
|---|---|---|
| 上手难度 | 低：套餐固定、控制台极简、**防火墙就是一张规则表** | 中：需理解 VPC、子网、**安全组**、带宽单独购买 |
| 计费 | 包月/包年，套餐含带宽 + 月流量包 | 包年包月或**按量计费**（按小时） |
| 价格 | 2核2G 月付 35 元（入门型，购买页实测） | 同规格更贵，且带宽/磁盘分开算 |
| 我们的用法 | `docker compose up` 跑三个容器 → **完全够用** | 用不到它的弹性伸缩、多盘挂载等能力 |
| 局限（答辩可能问） | 套餐固定不能随意加减内存；带宽为峰值共享 | 灵活，但"灵活"对单人项目是负担 |

**结论**：**买 Lighthouse，2核2G，月付。**

## 阶段五：服务器初始化（登录 → 放行端口 → 装 Docker）

### 5.1 首次登录（在本地 Windows PowerShell 里操作）

Windows 10 自带 `ssh` 命令，直接用：

```powershell
ssh ubuntu@你的公网IP
```

- 第一次会问 `Are you sure you want to continue connecting (yes/no)?` → 输入 **yes** 回车
- 然后提示 `ubuntu@IP's password:` → 输入 4.4 设的密码（**输入时屏幕不显示任何字符，这是正常的**）

**判定标准**：提示符变成 `ubuntu@VM-xx-xx:~$`，说明已经站在服务器里了。

> 💡 退出登录：敲 `exit` 回车。以后每次登录服务器都是这一条命令。

### 5.2 放行 8080 端口（★最容易漏、漏了必超时）

腾讯云轻量的防火墙**默认只开 22 / 80 / 443**，我们用的 8080 必须手动放行。

**面包屑**：控制台 → 轻量应用服务器 → 点实例 → 上方标签 **防火墙** → **添加规则**

| 字段 | 填什么 |
|---|---|
| 应用类型 | 自定义 |
| 协议 | TCP |
| 端口 | 8080 |
| 来源 | 0.0.0.0/0 |
| 策略 | 允许 |
| 备注 | blog-web |

**判定标准**：规则列表里出现这条 8080 记录。

⚠️ **这一步不做的典型症状**：服务器上 `docker compose ps` 一切正常，但浏览器访问公网 IP 一直转圈超时。这是 S7 最容易卡死的地方。

### 5.3 安装 Docker

**在服务器 SSH 会话里**执行（注意：这些命令在服务器上跑，不是在本地）：

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

**判定标准**：最后输出 `Docker version xx.x.x, build xxx`。

⚠️ 让用户组生效必须**退出重登**：

```bash
exit
```

然后重新登录（本地 PowerShell）：

```powershell
ssh ubuntu@你的公网IP
```

验证：

```bash
docker run --rm hello-world
```

**判定标准**：看到 `Hello from Docker!`。若报 `permission denied`，说明没重新登录。

**如果拉镜像超时**（国内的常见问题），配镜像加速后重试：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.1panel.live"
  ]
}
EOF
sudo systemctl restart docker
```

### 5.4 创建部署目录

```bash
mkdir -p ~/blog
```

**判定标准**：`ls ~` 能看到 `blog` 目录。目录里的文件由 CI 自动上传，**不需要你手动创建任何文件**。

## 阶段六：配置 GitHub Secrets

### 6.1 先准备两串密码和一个密钥

**（1）数据库密码**：自己定两个强密码（各 12 位以上，大小写+数字+符号，**不要**用 `root_pass_2026` 这种示例值）：

```
MYSQL_ROOT_PASSWORD = ________________（数据库 root 密码）
MYSQL_PASSWORD      = ________________（应用账号 blog 的密码）
```

**（2）JWT_SECRET**：在服务器上生成（SSH 会话里执行）：

```bash
openssl rand -hex 48
```

**判定标准**：输出一串 96 位的十六进制字符，复制保存。

**（3）服务器登录密钥（`SERVER_SSH_KEY`）** —— 两种方案二选一：

#### 方案 A：在服务器上生成（推荐给新手，命令最少）

服务器 SSH 会话里执行：

```bash
ssh-keygen -t ed25519 -f ~/.ssh/blog_deploy -N ""
cat ~/.ssh/blog_deploy.pub >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
cat ~/.ssh/blog_deploy
```

**判定标准**：最后一条命令输出以 `-----BEGIN OPENSSH PRIVATE KEY-----` 开头、以 `-----END OPENSSH PRIVATE KEY-----` 结尾的**完整内容**（中间几十行）。

**把这一整段（含首尾两行）复制下来**，下一步要贴到 GitHub。

> 为什么这样能行：`ssh-keygen` 在服务器上生成了钥匙对，公钥（`.pub`）已经追加进 `authorized_keys`（= 允许用这把钥匙进门），私钥内容交给 GitHub，让 Actions 拿它当钥匙来开门。
> 权衡：私钥会经过一次网络粘贴。GitHub Secrets 是加密存储的，对本项目来说安全够用；答辩若被问到更严格的做法，答"本地 `ssh-keygen` 生成、只把公钥传给服务器"。

#### 方案 B：本地生成（更规范）

本地 PowerShell 执行：

```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\blog_deploy -N '""'
type $env:USERPROFILE\.ssh\blog_deploy
```

然后把 **公钥**（`blog_deploy.pub`，以 `ssh-ed25519` 开头那行）的内容贴到服务器：

```bash
nano ~/.ssh/authorized_keys
```

（在 nano 里：鼠标右键 = 粘贴；`Ctrl+O` 回车 = 保存；`Ctrl+X` = 退出）

私钥（`blog_deploy` 那份，同样含首尾两行）用来填 GitHub Secret。

> ⚠️ 极其常见的错误：**把 `.pub` 公钥填进了 `SERVER_SSH_KEY`**。GitHub 里要的是**私钥**（没有 `.pub` 后缀的那个文件），且必须包含 `BEGIN` / `END` 两行。

### 6.2 填入 GitHub

**面包屑**：GitHub 仓库页 → 上方 **Settings** → 左侧 **Secrets and variables** → **Actions** → 右侧绿色按钮 **New repository secret**

逐个添加这 6 个（名字**必须一字不差**，全大写）：

| # | Secret 名称 | 值 |
|---|---|---|
| 1 | `SERVER_HOST` | 服务器公网 IP（如 `123.45.67.89`，**不要**带 `http://`，不要带端口） |
| 2 | `SERVER_USER` | `ubuntu` |
| 3 | `SERVER_SSH_KEY` | 6.1 得到的私钥全文（含 `BEGIN` / `END` 两行） |
| 4 | `MYSQL_ROOT_PASSWORD` | 6.1 自定义的 root 密码 |
| 5 | `MYSQL_PASSWORD` | 6.1 自定义的应用密码 |
| 6 | `JWT_SECRET` | 6.1 生成的随机长串 |

**判定标准**：列表里出现 6 条记录，每条显示"Updated now"。点进去能修改、但**看不到值**（这是正常的，说明真的加密存了）。

### 6.3 密码是怎么流转到服务器的

理解这条链路，答辩能加分：

```
GitHub Secrets（加密存储）
      │ CI 执行时注入为环境变量
      ▼
ci-cd.yml 的 deploy 步骤
      │ SSH 到服务器，现场写文件
      ▼
服务器 ~/blog/.env  ← 只存在于服务器，不落在 Git 里
      │ docker compose 读取
      ▼
容器环境变量（MYSQL_ROOT_PASSWORD / DATABASE_URL / JWT_SECRET ...）
```

关键点：**`deploy` 步骤每次都会重新生成 `.env`**，所以改密码只需要改 GitHub Secret，再跑一次流水线。

### 7.3 如果 Deploy 失败（对照表）

| 报错关键字 | 原因 | 解决 |
|---|---|---|
| `Permission denied (publickey)` | `SERVER_SSH_KEY` 填了公钥，或内容不完整（丢了首尾行） | 回阶段六 6.1 重新取私钥全文 |
| `dial tcp ... i/o timeout` / `connection timed out` | `SERVER_HOST` 填错，或带了 `http://` | 只填纯 IP |
| `docker: command not found` | 服务器装完 Docker 没重新登录 | 服务器上 `exit` 后重新 `ssh` 登录 |
| `unauthorized` / `denied` 拉镜像失败 | GHCR 镜像权限（私有包） | 仓库 Settings → 把该 Package 可见性设为 Public |
| `no such file or directory: apps/api/Dockerfile` | compose 试图在服务器上构建（源码不在这） | 确认 `docker-compose.prod.yml` 用的是 `build: !reset null` 写法 |

### 7.5 灌入种子数据（首次必须做）

## 阶段九：ICP 备案与域名（长期方案，非必须项）

### 9.1 为什么现在不做

中国大陆节点的 **80 / 443 端口**必须完成 ICP 备案才能对外服务。我们用 8080 端口交付，**完全规避了这个限制，当天就能上线**。

### 9.2 如果要做（时间线较长）

1. 控制台购买域名（或从其他注册商转入）
2. **面包屑**：控制台 → 搜索"备案" → 备案控制台 → 提交备案申请
3. 需要准备：身份证、服务器实例（**需购买满 3 个月**）、网站名称与简介
4. 腾讯云初审（1–2 天）→ 提交管局（**3–20 工作日**）→ 短信通知结果

### 9.3 备案通过后怎么切

改动很小，三处：

**① Nginx 监听 80 端口**（改 `docker-compose.prod.yml`）：

```yaml
services:
  web:
    ports:
      - "80:80"
      - "443:443"
```

**② 加 HTTPS**：用 Caddy 替换 Nginx 可自动申请续期 Let's Encrypt 证书，配置三行搞定：

```
blog.example.com {
    reverse_proxy web:80
}
```

（或继续用 Nginx + certbot）

**③ 更新交付链接**：`http://<IP>:8080` → `https://blog.example.com`
